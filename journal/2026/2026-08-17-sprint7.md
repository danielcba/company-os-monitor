# Journal — 2026-08-17 (Sprint 7 — Hypothesis Generator, Reasoning/Predict)

## Theme

Sprint 7 implementa la capacidad **Predict** (Concepto Hypothesis) del Reasoning Layer: el `hypothesis-service` propone explicaciones testables (candidatas) para cada anomalía point, instanciando las plantillas declarativas de la Hypothesis Template Library (procedural memory) con hechos medidos, y persistiendo filas en la tabla `hypotheses` (append-only, dedup idempotente). Gobernado por la regla conceptual: *"A hypothesis is a commitment to an explanation, held tentatively until evidence decides."* El sistema mantiene MÚLTIPLES hipótesis competidoras simultáneamente (convergencia prematura = fallo cognitivo) y no las confirma ni las descarta (`status='candidate'`; el descarte/confirmación requiere evidencia futura + Confidence, Sprint 8, fuera de alcance).

## Discoveries

- `predicted_consequences` es JSONB: el `HypothesisStore` debe serializar la lista con `json.dumps` antes del INSERT (asyncpg rechaza una lista Python para el `CAST(... AS jsonb)`), y parsearla al leer — patrón distinto a `observation_ids` (UUID[]) de evidence.
- La cadena de trazabilidad completa quedó verificada en integración: hypothesis → anomaly (`anomaly_ids`) → pattern (`anomaly.pattern_id`) → context (`anomaly.context_id`) → evidence (`context.evidence_ids`) → observations (`evidence.observation_ids`). La tabla `anomalies` ancla tanto el scope (vía context) como el patrón esperado (vía pattern_id), por lo que el generator lee contexts Y patterns aunque cada hipótesis solo referencia anomaly_ids/pattern_ids.
- El formato `{deviation_score:.1f}` exige que los placeholders se pasen como valores tipados (float), no pre-formateados a str: `_facts` devuelve `deviation_score` como float para que `str.format` aplique el especificador; `{frequency}`/`{scope}` como str.
- El ciclo live dedup acumula `total_hypothesis_duplicates` en cada corrida sobre la misma anomalía (esperado: el contador mide reintentos, las filas no se duplican).
- `write` (herramienta de agente) falla con contenido grande ("Unterminated string in JSON"): la Template Library se escribió en trozos (estructura primero, catálogo vía edit) y se reescribió compactando strings para respetar line-length 100.

## Decisions

- **Generator con stream de contexts + patterns**: `generate(anomaly, contexts, patterns, library)` — el scope se resuelve desde `anomaly.context_id` contra el stream completo; la pattern esperada desde `anomaly.pattern_id`. El servicio lee `list_anomalies` + `list_contexts` + `list_patterns` (todo read-only, P1).
- **≥2 hipótesis por anomalía (no-convergencia)**: assert interno + tests que verifican count ≥2 e ids distintos; el catálogo garantiza 3 competidoras por dominio. Convergencia prematura a una sola explicación = fallo cognitivo (regla del marco).
- **`coherence_score` declarativo del template**: `coherence_estimate` es un prior por explicación, documentado y purpose-dependent; el MVP lo persiste tal cual y NUNCA lo presenta como calibrado. La calibración real (S + C + ECE) llega con Confidence (Sprint 8).
- **`status='candidate'` siempre**: el generador no confirma ni falsifica; confirmación/falsificación requiere evidencia futura + Confidence (fuera de alcance). El trigger permite SOLO el flip de status.
- **Trigger de inmutabilidad con `status` como excepción**: a diferencia de `anomalies` (totalmente inmutable, sin ciclo de vida), `hypotheses` permite cambiar `status` pero bloquea cualquier otro UPDATE y todo DELETE. Justificado en el ciclo de vida candidate → confirmed/falsified.
- **LM Studio como herramienta externa opcional**: implementado el ABC `CognitiveTool`; si `available()` es falso → fallback solo templates (el flujo canónico nunca se queda sin salida). `validate_output` garantiza el contrato de falsificación en TODAS las hipótesis externas.
- **Sesión EVALUADA al inicio** (176 tests previos verdes). Sin cambios a prompts previos ni journals previos.

## Reflection

El sprint respeta la frontera del concepto: la hipótesis es un compromiso TENTATIVO con una explicación (nunca una conclusión: sin "es la causa"/"está confirmado"), SIEMPRE con predicción observable y criterio de falsificación concreto, y el sistema mantiene múltiples competidoras sin convergencia prematura. El patrón de los sprints previos (funciones puras + catálogo declarativo + dedup idempotente por id determinístico + trigger de inmutabilidad) se mantiene intacto, y la integración de LM Studio respeta ADR-0002 (externa, no-canónica, con fallback). El pipeline queda listo para Confidence (Sprint 8), que calibrará la coherencia y decidirá el destino de las candidatas.
