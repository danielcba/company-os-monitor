# Journal — 2026-08-17 (Sprint 8 — Confidence Calibration, Learning/Calibrate)

## Theme

Sprint 8 implementa la capacidad **Calibrate** (Concepto Confidence) del Learning Layer: el `confidence-service` conecta el Calibration Model al pipeline cognitivo y computa la **Confidence calibrada** de cada juicio bajo evaluación (las Hipótesis candidatas del Sprint 7), persistiendo filas completas en `confidence_scores` (append-only, dedup idempotente). Gobernado por las reglas conceptuales del marco: *"Confidence is not a feeling. It is a measurement."*, *"Confidence must be computed, not intuited."* y la falsificabilidad: *"The calibration factor is measured from outcomes only; it is never adjusted to justify a particular confidence."* Esta es la capacidad **transversal que habilita el Action Layer** (R4): todo juicio que influya acción debe llevar Confidence y sus razones.

## Discoveries

- La firma canónica de `confidence_id` con 7 argumentos choca con `PLR0913/PLR0917` de ruff: se refactorizó a un dataclass frozen `CalibrationContent` (S, C, 1−ECE, α) — el "contenido" de calibración que determina C_final — manteniendo 4 args y documentando el hash por contenido.
- La igualdad de objetos Pydantic en el test de anti-tuning falla por `computed_at` (microsegundos): la garantía de anti-tuning se verifica sobre id + score + justification (id y justification NO incluyen `computed_at`), no sobre la igualdad del objeto completo.
- El "último" `get_confidence` por `(target_type, target_id)` ordena por `computed_at DESC`; en tests con timestamp fijo hay que diferenciar `computed_at` entre calibraciones para que el tie-break devuelva la esperada (re-realidad: cada ciclo recalibra en un instante distinto).
- El ciclo live acumula `total_confidence_duplicates` en cada corrida sobre las mismas hypotheses (esperado: el contador mide reintentos, las filas no se duplican).
- `quality_class_to_weight` (banda canónica Q1=0.875, Q2=0.625, ...) coincide con el `weight` que el organizer asigna en Sprint 3 (punto medio de banda), por lo que S(H|E) es reproducible directamente desde `evidence.quality_class`.

## Decisions

- **`confidence_id` content-addressed incluyendo los inputs de calibración**: a diferencia del id de hypothesis (tenant + facts + descripción), el id de confidence hashea tenant + target + S + C + 1−ECE + α. Mismos inputs → mismo id (dedup); inputs distintos → nueva fila (append-only, P1: la calibración histórica se conserva y es auditable). Evaluado y resuelto el caso "nueva evidencia cambia el id": documentado y testeado.
- **`explanatory_coherence` como satisfacción de constraints normalizada**: C(H) = P/(P+N+U) sobre `{explains, contradicts, coherent_with, incoherent_with}`. Fracción de evidencia explicada en el scope, penalizada por contradicciones y evidencia no explicada (MVP documentado; consistencia entre hipótesis soportada por el esquema aunque el servicio la derive aún sin competidoras).
- **Esquema de signos +1/−1 desde `explains`/`contradicts`**: la evidencia cuya organization_type está declarada apoya (+1) u opone (−1); la neutral no contribuye a S (documentado: no toda la evidencia del tenant es relevante a un juicio). Pesos canónicos desde `quality_class_to_weight`.
- **Sin historial de outcomes → historical_calibration=1.0, ECE=0**: no existe aún un store de outcomes (Memory es fase futura), el servicio arranca con "primeros datos"; el calibrator soporta historial real (Brier/ECE) cuando llegue, sin cambiar la firma.
- **El servicio resuelve el scope vía la cadena completa** (hypothesis → anomaly → context → evidence) y lo declara como `explains`: el MVP no deriva constraints negativas (contradicts vacío, documentado como simplificación hasta que haya análisis entre hipótesis competidoras).
- **`confidence_scores` sin flag de ciclo de vida**: a diferencia de patterns/contexts/hypotheses (is_active/status), la fila es 100% inmutable (UPDATE y DELETE bloqueados) porque una nueva calibración es una nueva fila, nunca un update.
- **Puerto/env propios**: `CONFIDENCE_HEALTH_PORT=8095`, `CONFIDENCE_CYCLE_SECONDS`, `CALIBRATION_ALPHA`, `CALIBRATION_ECE_BINS`; L₀ fijo en 0 (prior no informativo, no hay base rate documentada). No se reutilizaron nombres de env previos.
- **Sesión EVALUADA al inicio** (198 tests previos verdes). Sin cambios a prompts previos ni journals previos.

## Reflection

El sprint respeta la frontera del concepto: la Confidence es una MEDIDA calibrada (S + C + ECE + C_final con parámetros fijos publicados), nunca una sensación ni un número tunificado para "sonar bien". El factor de calibración se mide solo de outcomes (aquí, primer dato = 1.0 documentado), y el determinismo puro garantiza la falsificabilidad (mismo input → mismo score, auditable post hoc). P1 se mantiene en la capa de datos: `confidence_scores` es append-only con trigger de inmutabilidad y re-ejecución idempotente, y el servicio solo LEE los artefactos previos. Esta capacidad es la habilitadora del Action Layer (R4): a partir de aquí, todo juicio que influya acción debe llevar Confidence y sus razones — las Recommendations (Sprint 9) y Decisions (Sprint 10) la consumirán como input obligatorio por el mismo path (`target_type='recommendation'/'decision'`).
