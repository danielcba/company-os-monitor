# Journal — 2026-08-19 (Fase 5)

## Theme

Fase 5 del frontend COS-Monitor: vista Contexts con las interpretaciones
activas reales del pipeline. Se añade al API Gateway el endpoint READ
`GET /api/v1/tenants/{tenant_id}/contexts` (paginado, filtrable por
`purpose`/`mental_model_id`/`is_active`, tenant scope) y su detalle
`GET /api/v1/tenants/{tenant_id}/contexts/{context_id}` con el **desglose de
evidence** (el soporte, resuelto desde la tabla canónica `evidence` vía
`evidence_ids`), y el producto web lo renderiza como tabla de activaciones con
el modelo mental ganador, su coherence score y los `competing_models` con sus
puntuaciones, más un drawer con la competencia y el desglose de evidence.

El frontend sigue siendo capability externa (ADR-0002): representa Context
mostrando el modelo ganador y sus competidores, nunca lo genera (P2 — Context
se selecciona por competencia de coherencia, no se crea directo), y el
contenido de una activación es inmutable (P1) — solo el flag `is_active` es de
ciclo de vida. Todo pasa por el Gateway (R3).

## Observations & Insights

- **`CAST(:is_active AS BOOLEAN)` verificado contra la BD real**: el listado
  sin filtro devuelve los 3 contexts (NULL → sin filtro) y `is_active=false`
  devuelve 0 honesto (todos los contexts reales están activos). El patrón
  asyncpg NULL-safe funcionó en vivo, igual que el `CAST AS VARCHAR` de Fase 3.
- **Facets reales**: 3 purposes (security_posture, infrastructure_health,
  capacity_management) y 2 mental model ids (service_failure, capacity_risk);
  coherence 0.33 en todas las activaciones; la competencia muestra honestos
  scores 0 (p. ej. auth_compromise 0.0) — el UI los renderiza sin suavizarlos.
- **No se exponen las descripciones del catálogo de mental models** en el
  drawer: el Gateway se mantiene READ puro (R3) y no reimplementa contenido
  cognitivo; la vista muestra ids canónicos.
- Los 3 evidence del desglose son Q1 weight 0.88 (resource_exhaustion /
  service_degradation / backup_failure): coherente con la Fase 4, todo el
  pipeline real sigue siendo de medición directa.

## Decisions & Trade-offs

- **Filtros por facets reales y no por lista fija** (como Fases 3–4): el UI
  no inventa opciones; solo muestra lo que el tenant tiene de verdad.
- **`CognitiveContext` en vez de `Context`** como tipo: evita la colisión con
  el `Context` de React y deja el contrato explícito en el código.
- **El detalle de evidence usa `_evidence_payload`** del `EvidenceReadStore`:
  no se duplica la lógica de serialización de evidence; el desglose de
  contexts y el de evidence quedan consistentes.
