## Discoveries

### El shape real de services/health difiere del supuesto

`check_service_health` en `apps/gateway/api-gateway/src/service.py:185` devuelve
`{service, url, status, healthy}` (status = código HTTP, healthy = bool), no
`{name, status: "healthy"}`. El frontend se alineó al contrato real (los tests
se escribieron contra el mock del contrato correcto).

### login + `/me` en AuthProvider

`signIn` solo persiste los tokens y el efecto de `accessToken` carga el perfil
vía `/me`; así se evita doble fetch y el estado queda consistente con las rutas
protegidas (`isLoading` mientras se resuelve `/me`).

## Decisions

- **Frontend = external capability (ADR-0002)**: representa conceptos, nunca
  los redefine ni ejecuta lógica cognitiva en el browser. Las design rules
  R1–R2 vinculan a los componentes cognitivos, no a la UI del producto; la
  doc de arquitectura describe el mapeo 1:1 de vistas a capacidades de forma
  factual, sin citar R1/R2.
- **UI en inglés, conceptos cognitivos sin traducir** (Observations, Evidence,
  Context, Pattern, Anomaly, Hypothesis, Insight, Confidence, Recommendation,
  Decision).
- **CORS mínimo y explícito**: solo origen dev `http://localhost:5173`,
  GET/POST/OPTIONS, headers Authorization/Content-Type. No se abre el CORS a
  ningún otro origen.
- **Estados honestos obligatorios**: LoadingState/EmptyState/ErrorState/
  UnauthorizedState/ForbiddenState/NotAvailable. Nunca se fabrica un dato
  (P1: observations inmutables; la UI no genera evidencia ni conclusiones).
- **Tipos TS escritos a mano** contra los modelos reales (no hay OpenAPI);
  se alinean al contrato real (`services/health` devuelve
  `{service, url, status, healthy}`).
- **Insight** se representa en el flujo cognitivo del dashboard como parte de
  Reasoning (canónico), aunque su servicio aún no tiene endpoint READ.

## Reflection

La fase se mantuvo dentro de la policy: el frontend no toca BD/Redis, todo
pasa por el API Gateway (R3), y los conceptos se muestran sin reinterpretarlos.
La verificación en vivo (login 200, services/health 200 con bearer+origin,
CORS 204) confirmó que el contrato real manda sobre los supuestos: el shape de
services/health no era `{name,status}` sino `{service,url,status,healthy}`.
El costo fue bajo y el framework siguió guiando el código (R7).
