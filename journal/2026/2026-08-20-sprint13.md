# Sprint 13 — Insight Service

## Objective

Build the Insight service as the canonical link between Hypothesis and Recommendation in the Company OS cognitive chain (boundary.py: `hypothesis → insight → recommendation`). An Insight is a novel understanding that results from restructuring the relationship between existing knowledge elements — it is not new information, it is a new organization of information that was already available (core-concepts/insight.md).

The service detects competitive frames (multiple candidate hypotheses over the same Active Context) and journals the transformation (prior understanding + new organization + mental model update). "Insight cannot be forced or scheduled": the declarative rule only fires when the condition is met by existing knowledge.

## Design Highlights

### 1. `libs/reasoning/insight.py` — Model + deterministic id + append-only store
- INSIGHT_NAMESPACE = `00000000-0000-0000-0000-000000000083` (content-addressed, idempotent)
- `insight_id(tenant, context_id, hypothesis_ids, description)` — deterministic; same restructuring over same knowledge → same id (dedup); new hypotheses → new row (append-only, P1)
- Insight has no lifecycle status column: fully immutable content, no UPDATE/DELETE possible (content trigger enforces P1)
- InsightCreate/Insight pydantic models with frozen=True; mental_model_update as declarative jsonb frame

### 2. `libs/procedural_memory/insight_rules.py` — Declarative rule library
- MVP rule: **competitive_frame** — fires when ≥2 hypotheses coexist in the same Active Context
- Description template (factual, no invention): "El marco actual mantiene {n} hipótesis candidatas en competencia sobre el scope {scope} (contexto {context_id}): la explicación no ha convergido prematuramente en una única causa. La organización del conocimiento se reestructura tratando esas {n} explicaciones como interpretaciones alternativas de una misma desviación observada (anomalías {anomaly_ids})."
- prior_understanding template: verbatim concatenation of the competing hypothesis descriptions
- mental_model_update: `{"frame": "single-deviation-multi-explanation", "context_id", "scope", "hypothesis_ids", "anomaly_ids"}` — purely declarative

### 3. `apps/services/insight-service/` — Full service (mirrors hypothesis-service pattern)
- `src/main.py` — entry point (port 8101, cycle 60s)
- `src/service.py` — InsightService: per-tenant restructure cycle → group hypotheses by ACTIVE Context (traceability: hypothesis → anomaly → context) → apply rule → persist InsightCreate
- `src/generator/generator.py` — pure function: `_active_context`, `_competitive_frames`, `generate_insights`
- `src/health.py` — /health + /metrics on 8101
- `pyproject.toml` + `Dockerfile` — mirror hypothesis-service template
- `tests/test_insight_generator.py` + `tests/test_insight_store.py` — unit tests (pure functions + store dedup)

### 4. `infrastructure/db-migrations/sprint13-insight-content-trigger.sql` — P1 enforcement
- Full immutability trigger: no UPDATE or DELETE on insights (the row is a permanent audit trail)
- No status column → all content columns immutable

### 5. Integration — recommendation-service (additive, optional provenance)
- `formulate()` now accepts `insight: Insight | None = None` parameter
- When insight is provided and covers the hypothesis (hypothesis.id ∈ insight.hypothesis_ids), the rationale cites the insight as provenance and `insight_id` is set in the RecommendationCreate
- The service loads insights from the DB per tenant and maps hypothesis_id → insight (optional; if no insights exist, formulate proceeds as before with `insight=None`)
- `libs/action/recommendation.py` already had `insight_id: uuid.UUID | None = None` in the model — Sprint 13 just fills it when applicable
- Tests: 33/36 pass (3 pre-existing failures unchanged); the 3 new insight-service tests pass

### 6. Infra
- `start.sh` — added `insight|apps/services/insight-service|INSIGHT_HEALTH_PORT|8101` after hypothesis
- `.env.example` — added `INSIGHT_CYCLE_SECONDS=60` + `INSIGHT_HEALTH_PORT=8101`
- `apps/gateway/api-gateway/src/summary.py` — `COUNT_TOTALS` now includes `(SELECT COUNT(*) FROM insights ... AS insights)`
- `apps/gateway/api-gateway/src/service.py` — `DEFAULT_SERVICE_HEALTH` now includes `"insight": "http://localhost:8101/health"`

## Cognitive Chain Impact

The boundary chain now reads: `observation → evidence → context → pattern → anomaly → hypothesis → insight → recommendation → decision → execution`.

Insight "leads To" Recommendation in the canonical framework. The insight service is the restructuring capability that the framework design implies but had not yet implemented. It respects all P1 constraints (append-only, never retrofitted, never invents facts) and the principle that Insight "cannot be forced or scheduled" — the declarative rule only fires when the competitive frame genuinely exists.
