# 2026-08-25 — Correcciones CI (correcciones_finales_7.md)

## Objetivo
Llevar la CI a verde **porque el código es correcto**, clasificando cada fallo
antes de modificarlo (Fase A producción → Fase B aislamiento → Fase C tests
obsoletos → Fase D clasificación), sin debilitar controles de seguridad ni el
Framework Company OS.

## Bugs reales de producción corregidos
1. **`libs/learning/confidence.py`** — `list_confidence` construía el SQL como
   `SELECT_CONFIDENCE + text(" LIMIT ...")` (dos `TextClause` concatenados) →
   `TypeError`. Se añadió `SELECT_CONFIDENCE_PAGED` con `LIMIT/OFFSET`
   parametrizados. Regression: `test_list_confidence_pagination_slices_rows`.
2. **`apps/services/recommendation-service/src/service.py`** — `get_confidence`
   se invocaba sin `tenant_id` (contrato Phase 12). La excepción era tragada por
   `asyncio.gather(..., return_exceptions=True)`, produciendo 0 recomendaciones y
   contadores erróneos. Se pasa `tenant_id=tenant_id`. Los tests
   `test_service_formulates_with_traceability_and_p1` y
   `test_service_skips_hypotheses_without_confidence` (ya existentes) sirven de
   regresión.
3. **`libs/perception/context.py`** — `save_context` insertaba el contexto
   `is_active=true` **antes** de desactivar el previo del mismo
   `(tenant_id, purpose)`, violando el índice parcial `idx_contexts_unique_active`.
   Se invierte el orden: desactivar el contexto activo previo **antes** del
   INSERT, dentro de la misma transacción atómica (Phase 5). No se debilitó el
   índice ni el trigger de inmutabilidad. Esto resuelve de raíz las violaciones
   en anomaly/context/pattern. Regression:
   `test_new_activation_supersedes_previous_active_context`.

## Aislamiento / fixture
- **`anomaly-service/tests/test_anomaly_store.py`** —
  `test_service_detects_persists_and_traces` dependía del tenant *sandbox*
  compartido teniendo 3 contextos activos sin patrón (contaminación de estado
  global, no determinista). Se siembran 3 contextos propios sin patrón
  coincidente (no generan anomalías) para hacer el test autocontenido. Se ajustó
  el conteo P1 `unchanged["ctx"]` de 2 a 5 (el ciclo no escribe en `contexts`).

## Tests obsoletos actualizados al contrato vigente
- `context-service` y `pattern-service`: `set_active(id=, is_active=)` → añadido
  `tenant_id=` (Phase 12).
- `insight-service`: `build_insight` importaba la API vieja
  `insight_rules.build_insight(rule, tenant_id, context, hypotheses)`; se cambió
  a la canónica `libs.reasoning.insight.build_insight(create: InsightCreate)`.
- `report-service` (`test_renderers.py`): `section_7_learning_loop` ahora se
  puebla por decisión (comportamiento arquitectónicamente correcto); el assert
  `== []` se reemplazó por no-vacío con claves esperadas.
- `report-service` (`test_report_store.py`): los handlers `/api/v1/reports`
  ahora exigen JWT (Phase 20.1). Se mintea/adjunta Bearer token y se añade
  `test_generate_handler_without_token_is_401`; se preserva el control de
  seguridad (no se desactivó auth).
- `gateway/api-gateway/tests/test_cors.py`: setup incorrecto — rutas añadidas a
  `cors` antes de registrarlas, wildcard `"*"` inválido para preflight en
  aiohttp_cors 0.8.1, y faltaban `Access-Control-Request-Method/Headers`.
  Corregido para validar el comportamiento real (preflight 200 con cabeceras
  para origen permitido; 403 para origen no permitido).
